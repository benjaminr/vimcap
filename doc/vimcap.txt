1. INTRODUCTION                                          *vimcap-introduction*

vimcap turns Vim into a hex editor for packet captures. Opening a .pcap,
.pcapng or .cap file shows one packet per line as space-separated hex bytes,
dissected by scapy:

  - each protocol layer's bytes are coloured differently,
  - the statusline names the exact field under the cursor
    (e.g. "pkt 3/120  byte 0x16  IP.ttl = 64"),
  - |w| and |b| jump between protocol fields instead of words,
  - a dissection column on the right shows the full protocol tree for the
    packet under the cursor, following it as you move; |K| toggles it,
  - annotations and panes re-dissect automatically as you edit
    (|vimcap-live|),
  - saving writes a valid capture back, preserving the link type and
    per-packet timestamps (an unedited save is byte-identical).

==============================================================================
2. REQUIREMENTS                                          *vimcap-requirements*

  - Vim 8.2+ with |textprop| support, or Neovim
  - Python 3.7+ (standard library only for the hex editor)
  - scapy (https://scapy.net), optional — unlocks dissection: colours, the
    field inspector and the filter/follow/stats/craft toolbox

Without scapy the hex editor still opens, edits and saves captures
byte-faithfully; only the dissection layer is unavailable. Run the bundled
install.sh (or `pip install scapy`) to add it.

The Python interpreter is invoked as an external command, so Vim does not
need |+python3|. When |g:vimcap_python| is unset, vimcap auto-discovers one:
it prefers the bundled .venv (created by install.sh), then python3/python,
choosing the first that has scapy. |:VimcapHealth| shows what was found.

==============================================================================
3. USAGE                                                        *vimcap-usage*

Open a capture: >

    vim capture.pcap
<
Edit bytes with ordinary Vim editing: |r| to replace a nibble, |R| to
overtype a run of bytes, |dd| to delete a packet, |yy| and |p| to duplicate
one. Each line must contain an even number of hex digits when you save.

                                                                 *vimcap-live*
Annotations update themselves as you edit: changes are debounced briefly
(|g:vimcap_live_delay|), then the edited packets are re-dissected by a
persistent helper process, refreshing the layer colours and field names
almost instantly. In Neovim, or with |g:vimcap_live| disabled, annotations
go stale on edit instead ("[edited]" in the statusline) until you run
|:VimcapRefresh| or save. If the helper cannot be started, live updates
switch themselves off with a warning and editing continues as normal.

Write with |:w| as usual. New packets added at the end inherit the previous
packet's timestamp.

4. COMMANDS                                                  *vimcap-commands*

All commands are buffer-local to capture buffers.

Panes are laid out around the hex window in two regions: a full-height
column on the right (dissection tree, summaries, stream, stats) and a stack
underneath the hex (the byte-aligned ASCII, binary and UTF-8 views). Which
panes open on load, in what order, which region each belongs to, and how big
they are, are all configurable -- see |vimcap-layout|.

All open panes keep themselves up to date as the buffer changes, and all of
them track the cursor: the ASCII and binary views point at the byte under
the hex cursor, the summary and UTF-8 views at its packet, and the
dissection tree re-renders for it. The mouse can scroll and focus any pane
(|g:vimcap_mouse|); wheeling a line-bound pane scrolls the hex window with it.

                                                                *:VimcapAscii*
:VimcapAscii            Open a bottom split rendering each byte as printable
                        ASCII, column-aligned with the hex and bound to its
                        cursor.

                                                                 *:VimcapBits*
:VimcapBits             Open a bottom split rendering each byte as binary:
                        █ for a set bit, · for a clear one, most significant
                        bit first, one group per byte. Colours come from
                        the VimcapBitOn / VimcapBitOff highlight groups.

                                                                 *:VimcapUtf8*
:VimcapUtf8             Open a bottom split with each packet decoded as
                        UTF-8 text.

                                                              *:VimcapSummary*
:VimcapSummary [proto]  Open a pane with scapy's one-line summary per
                        packet, scroll-bound to the hex window. With [proto]
                        (e.g. "IP"), dissection starts at that protocol
                        instead of the capture's link type.

                                                               *:VimcapDetail*
:VimcapDetail [proto]   Dissection pane for the packet under the cursor: a
                        styled header (packet N/total, timestamp, length), the
                        protocol path, and each layer's fields with their byte
                        offsets, values and bad-checksum markers; the field
                        under the cursor is highlighted and the pane scrolls to
                        it. The pane opens automatically when a capture loads
                        (|g:vimcap_panes|), follows the cursor from packet to
                        packet, and |K| toggles it. With [proto] it falls back
                        to scapy's own show() starting at that protocol.

                                                              *:VimcapRefresh*
:VimcapRefresh          Re-dissect the buffer contents to update colours,
                        summaries and field annotations after editing.

                                                               *:VimcapClose*
:VimcapClose            Close every vimcap pane (and the agent terminal),
                        leaving just the hex window. From the hex window press
                        Q (or >q); from inside any pane press q.

                                                                 *:VimcapHelp*
:VimcapHelp             Toggle the welcome splash: the vimcap logo and a quick
                        command reference. It opens on its own when you start
                        an empty session (|g:vimcap_welcome|) and closes once
                        packets arrive. Also on |>?|.

                                                                *:VimcapTheme*
:VimcapTheme [name]     Switch the colour theme live (|g:vimcap_theme|), with
                        tab-completion of the available names. With no
                        argument, report the current theme. Available
                        anywhere, not just in a capture buffer.

                                                               *:VimcapHealth*
:VimcapHealth           Report the environment vimcap depends on: editor
                        features, the Python interpreter and scapy version it
                        found, and whether the agent CLI is present. Available
                        anywhere, not just in a capture buffer.

                                                                  *:VimcapFix*
:[range]VimcapFix       Recompute checksums and length fields (defaults to
                        the whole buffer). Packets whose checksums are wrong
                        are flagged with ✗ in the statusline.

                                                                  *:VimcapSet*
:VimcapSet {field}={value}
                        Set a protocol field on the current packet by name,
                        e.g. ':VimcapSet ttl=12' or ':VimcapSet IP.dst=10.0.0.9'.
                        Values parse as integers (0x.. works) or strings.
                        Checksums and lengths are recomputed around the
                        change. |>f| prompts with the field under the cursor.

                                                                  *:VimcapNew*
:VimcapNew {expr}       Append a packet built from a scapy expression below
                        the cursor, e.g.
                        ':VimcapNew Ether()/IP(dst="10.0.0.1")/ICMP()'.

                                                              *:VimcapCommand*
:VimcapCommand          Yank the scapy expression that rebuilds the current
                        packet into the unnamed and clipboard registers --
                        handy for turning captures into scripts or fixtures.

                                                               *:VimcapFilter*
:VimcapFilter {expr}    Fold away packets not matching {expr}: a bare layer
                        name (':VimcapFilter DNS') or a Python expression
                        over 'p' (':VimcapFilter p[TCP].dport == 80').
:VimcapFilter[!]        Clear the filter.

                                                               *:VimcapFollow*
:VimcapFollow           Fold to the current packet's TCP/UDP conversation
                        and show its reassembled payloads in a pane, with
                        '->' and '<-' marking the direction.

                                                                 *:VimcapGrep*
:VimcapGrep {pattern}   Regex-search the decoded packet payloads and load
                        the matches into the |quickfix| list; each entry
                        jumps to the matching packet and byte.

                                                                *:VimcapStats*
:VimcapStats            Capture overview in a pane: packet and byte counts,
                        duration, protocol stacks, conversations and ports.

                                                                 *:VimcapAnon*
:VimcapAnon             Consistently rewrite MAC and IP addresses across the
                        capture (02:00:00:...:NN / 10.99.x.x / fd00::x) for
                        sharing. Payload contents are left alone; checksums
                        are recomputed. Undo with |u|.

                                                                *:VimcapSniff*
:VimcapSniff {iface} [count]
                        Capture packets from an interface (default 10, with
                        a |g:vimcap_sniff_timeout| ceiling). On Vim with
                        |+job| packets stream into the buffer live, appearing
                        one at a time as they are captured; other runtimes
                        append them all when the capture finishes. Requires
                        capture privileges. Opening a new, empty capture (e.g.
                        "vim live.pcap" on a file that does not exist yet)
                        gives you a ready vimcap session; the first packets to
                        land lay out the configured panes (|g:vimcap_panes|)
                        just like loading a file.

                                                            *:VimcapSniffStop*
:VimcapSniffStop        Stop a running |:VimcapSniff| early, keeping whatever
                        has been captured so far.

                                                                 *:VimcapSend*
:[range]VimcapSend [iface]
                        Transmit the packets in [range] (default: all) on an
                        interface. Disabled unless |g:vimcap_allow_send| is
                        set, and needs raw-socket privileges.

                                                                 *:VimcapDiff*
:VimcapDiff {file}      Diff this capture against another, vimdiff-style
                        over the hex lines.

                                                 *:VimcapAgent* *vimcap-agent*
:VimcapAgent [task]     Agentic mode: open an AI agent (Claude Code by
                        default, |g:vimcap_agent_cmd|) in a vertical
                        terminal split, wired to this session over an MCP
                        bridge. The agent gets structured tools -- read
                        packets and dissections, move your cursor (all the
                        panes follow), set fields, fix checksums, filter,
                        follow streams, grep, edit/insert/delete packets --
                        and you watch every action live. Give it a [task]
                        ("why does packet 12 look corrupt?") or let it
                        explore. Talk to it in the terminal as usual.

                        The bridge listens on 127.0.0.1 with a per-session
                        token, and the agent can only reach the operations
                        above; raw ex commands need |g:vimcap_agent_raw|.
                        Any MCP client can attach the same way: the config
                        written for Claude Code points at
                        'python3 vimcap.py mcp --session {file}'.

:VimcapAgent!           Stop the agent session and close its terminal.

                                                                 *:VimcapGoto*
:VimcapGoto {offset}    Move the cursor to a byte offset within the current
                        packet. Accepts decimal (20) or hex (0x14).

                                                                *:VimcapValue*
:'<,'>VimcapValue       Interpret the visually selected bytes: byte count,
                        hex run, ASCII text, and (up to 8 bytes) big- and
                        little-endian integer values. Also on |K| in visual
                        mode.

==============================================================================
5. MAPPINGS                                                  *vimcap-mappings*

Normal mode (buffer-local):

    h / l           move one byte left/right
    w / b           jump to the next/previous protocol field
    K               toggle the dissection pane (|:VimcapDetail|)
    >f              edit the field under the cursor (|:VimcapSet|)   *vimcap->f*
    >a              ASCII pane (|:VimcapAscii|)
    >b              binary pane (|:VimcapBits|)
    >u              UTF-8 pane (|:VimcapUtf8|)
    >s              summary pane (|:VimcapSummary|)
    >q / Q          close all panes (|:VimcapClose|)                *vimcap->q*
                    (Q is a single key; >q can lag behind the '>' operator)
    q (in a pane)   close all panes from within any pane
    >?              toggle the welcome splash (|:VimcapHelp|)        *vimcap->?*

Visual mode:

    K               interpret the selected bytes (|:VimcapValue|)

Set |g:vimcap_byte_motions| to 0 to keep Vim's standard h/l/w/b behaviour.

6. CONFIGURATION                                        *vimcap-configuration*

g:vimcap_python                                              *g:vimcap_python*
    Python interpreter used to run the helper script. Leave unset to let
    vimcap auto-discover one (the bundled .venv, then python3/python,
    preferring whichever has scapy); set it to pin a specific interpreter.
    Default: unset (auto-discover)

g:vimcap_byte_motions                                  *g:vimcap_byte_motions*
    Remap h/l to byte motions and w/b to field jumps. Default: 1

g:vimcap_statusline                                      *g:vimcap_statusline*
    Replace the statusline with packet/byte/field information. Default: 1

g:vimcap_highlight                                        *g:vimcap_highlight*
    Colour each protocol layer's bytes. Default: 1

g:vimcap_annotate_limit                              *g:vimcap_annotate_limit*
    Maximum number of packets to dissect for colours, summaries and field
    annotations (large captures stay fast; packets beyond the limit are
    still fully editable). Default: 2000

g:vimcap_default_linktype                          *g:vimcap_default_linktype*
    Link type used when creating a capture from an empty buffer.
    Default: 1 (Ethernet)

g:vimcap_live                                                  *g:vimcap_live*
    Re-dissect packets automatically as the buffer changes (|vimcap-live|).
    Default: 1

g:vimcap_live_delay                                      *g:vimcap_live_delay*
    Milliseconds of idle time after an edit before re-dissection runs.
    Default: 300

g:vimcap_live_timeout                                  *g:vimcap_live_timeout*
    Milliseconds to wait for the helper daemon before giving up and
    disabling live updates. Default: 3000

                                                             *vimcap-layout*
Layout and pane configuration ~

g:vimcap_panes                                                *g:vimcap_panes*
    Ordered list of panes opened automatically when a capture loads, from
    "detail", "ascii", "bits", "summary", "utf8" and "stats". The order is
    the order they stack within their region. Set to [] to open nothing.
    (g:vimcap_auto_panes is accepted as an alias.)
    Default: ['detail', 'ascii', 'bits']

g:vimcap_pane_region                                    *g:vimcap_pane_region*
    Dictionary overriding which region a pane opens in -- "right" for the
    full-height column beside the hex, "bottom" for the stack underneath it.
    Only the panes you name are affected. For example, to put the binary
    view in the right column: >
        let g:vimcap_pane_region = {'bits': 'right'}
<    Defaults: detail/summary/stream/stats -> right; ascii/bits/utf8 ->
    bottom.

g:vimcap_pane_width                                      *g:vimcap_pane_width*
    Width (columns) of the right-hand pane column, clamped to half the
    screen. Default: 64

g:vimcap_pane_height                                    *g:vimcap_pane_height*
    Height (lines) of a bottom pane, clamped to half the screen.
    Default: 10

g:vimcap_pane_size                                        *g:vimcap_pane_size*
    Dictionary overriding the cross-size (height, in lines) of individual
    panes, e.g. 'let g:vimcap_pane_size = {"detail": 25, "ascii": 6}'.
    Takes precedence over |g:vimcap_pane_width| / |g:vimcap_pane_height|.
    Default: {}

g:vimcap_mouse                                                *g:vimcap_mouse*
    Enable the mouse (:set mouse=a) when a capture loads, so panes can be
    scrolled and focused by pointing at them. Only applies when 'mouse' is
    empty, so an existing preference always wins. Default: 1

g:vimcap_allow_send                                      *g:vimcap_allow_send*
    Allow |:VimcapSend| to transmit packets. Off by default because it puts
    traffic on the wire. Default: 0

g:vimcap_sniff_timeout                                *g:vimcap_sniff_timeout*
    Seconds |:VimcapSniff| waits for its packet count before returning with
    whatever it has. Default: 15

g:vimcap_agent_cmd                                        *g:vimcap_agent_cmd*
    The agent CLI |:VimcapAgent| launches. Default: "claude"

g:vimcap_auto_agent                                      *g:vimcap_auto_agent*
    Start the agent automatically when a capture loads. Off by default --
    the agent begins analysing (and spending tokens) as soon as it opens, so
    it is opt-in; run |:VimcapAgent| when you want it. When enabled it only
    applies in an interactive Vim with the agent CLI installed, and stands
    down for the rest of the session once dismissed with :VimcapAgent!.
    Default: 0

g:vimcap_agent_raw                                        *g:vimcap_agent_raw*
    Allow the agent to run raw Vim ex commands through its 'ex' tool. Off
    by default: the structured tools cover capture work, and raw ex hands
    the agent your whole editor. Default: 0

g:vimcap_agent_position                              *g:vimcap_agent_position*
    Where the agent terminal opens: "right" (default), "left" or "bottom".

g:vimcap_agent_width                                    *g:vimcap_agent_width*
    Width (columns) of the agent terminal when it opens left/right.
    Default: 80

g:vimcap_agent_height                                  *g:vimcap_agent_height*
    Height (lines) of the agent terminal when it opens at the bottom.
    Default: 15

g:vimcap_welcome                                            *g:vimcap_welcome*
    Show the welcome splash (logo + command reference) automatically when a
    session opens with no packets. Toggle it anytime with |:VimcapHelp|.
    Default: 1

g:vimcap_theme                                                *g:vimcap_theme*
    Colour theme, applied across every pane so the panes read as a set (an
    IP layer is the same colour in the hex bytes, the detail heading and the
    summary). One of: >
        mono      greyscale shades + a single accent (the default)
        neon      vibrant cyan/green/magenta/amber on a dark ground
        warm      softer solarized-style amber/teal/olive/rose
        classic   link to your colourscheme's groups (no fixed colours)
<    Set it in your vimrc, or switch live with |:VimcapTheme|. Default: "mono"

g:vimcap_themes                                              *g:vimcap_themes*
    Dictionary of extra themes (or overrides of the built-ins), each a map of
    semantic roles to [cterm, "#guihex"] pairs. Roles: accent, error, bright,
    normal, dim, dimmer, l0, l1, l2, l3, payload. For example: >
        let g:vimcap_themes = {'ocean': {
              \ 'accent': [39, '#00afff'], 'error': [203, '#ff5f5f'],
              \ 'bright': [195, '#d7ffff'], 'normal': [152, '#afd7d7'],
              \ 'dim': [66, '#5f8787'], 'dimmer': [238, '#444444'],
              \ 'l0': [51, '#00ffff'], 'l1': [39, '#00afff'],
              \ 'l2': [63, '#5f5fff'], 'l3': [99, '#875fff'],
              \ 'payload': [238, '#444444']}}
        let g:vimcap_theme = 'ocean'
<    Default: {}

7. HIGHLIGHTING                                          *vimcap-highlighting*

Themes (|g:vimcap_theme|) set the highlight groups for you. To tweak colours
without a whole theme, override any group after vimcap loads (the groups are
re-applied on |ColorScheme|, so set them in a ColorScheme autocommand to make
them stick). The groups:

    VimcapLayer0..3      the protocol layers, outermost first
    VimcapPayload        Raw / Padding bytes
    VimcapCursorByte     the byte under the cursor
    VimcapBitOn/BitOff   set / clear bits in the binary pane
    VimcapHeader         pane header lines
    VimcapPath           the Ether > IP > TCP path; VimcapPathSep the ">"
    VimcapRule           separator rules
    VimcapLayerName      layer headings in the detail/stats panes
    VimcapOffset         byte offsets in the detail pane
    VimcapValue/Field    field values / names
    VimcapVendor         MAC-vendor annotations
    VimcapBad            bad-checksum markers
    VimcapFieldCursor    the detail row for the field under the cursor
    VimcapBar/BarTrack   filled / empty parts of the stats bars

8. LIMITATIONS                                            *vimcap-limitations*

  - pcapng files are read transparently but are saved in classic pcap
    format (a warning is shown); Wireshark and tcpdump read both.
  - Captures whose packets span multiple link types (multi-interface
    pcapng) are dissected using the first packet's link type.
  - Nanosecond-precision timestamps are rounded to microseconds on save.
  - Inserting or deleting packets in the middle of a capture cannot keep the
    exact timestamps of the packets after the edit: times are preserved up to
    the first changed packet and carried forward from there.
  - Editing a packet's bytes makes its length authoritative, so a genuinely
    wire-truncated packet (captured shorter than it was on the wire) loses
    its original wire length when re-saved after an edit.
  - The whole capture is held in the buffer; multi-gigabyte captures are
    better trimmed first (e.g. with tcpdump -c).
